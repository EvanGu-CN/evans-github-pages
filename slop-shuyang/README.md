# Slop 沭阳

用 [three.js](https://threejs.org/) WebGPURenderer 与 TSL 着色器搭建的江苏沭阳 3D 城市仿真，按 1 单位 = 1 米组织沭阳城区：人民路、上海路、北京路、苏州路、迎宾大道等道路，新沂河/淮沭河/柴沂河与城区河道，街区建筑、公园绿地，以及 17 处可传送地标。

只渲染城区核心：东西约 6.6 km、南北约 7.4 km，约 48.8 km²（北到台州路森林公园/城北公园，南到学院路体育中心/南湖，西到八一广场，东到虞姬公园/政务中心）。乡镇、村庄和开发区远端不纳入。

支持步行、驾车、骑行、直升机四种出行方式，第三人称跟随、低角度追车、驾驶舱、多处风光机位与自动巡游航拍，以及实时小地图和全屏街道图。

本项目是 [Slop New York](https://github.com/mrdoob/slop-newyork/) 的城市替换版：保留其渲染、交通、行人和音频引擎，把城市内容层从曼哈顿换成了沭阳。城区范围、代表地标清单与加载策略参考了 [Slop 武汉](https://github.com/LightYearZh/slop-wuhan) 的做法。

## 地图（纯矢量 A 方案）

小地图与全屏街道图直接用 3D 城市同一份 OSM 数据绘制，不依赖外部瓦片，离线可用：

- 水面多边形、河道中心线、公园与绿地
- 机动车道、步道、自行车道、小路、桥梁、铁路
- 7,558 栋 OSM / Overture 来源建筑轮廓（保留内院，高亮较高建筑）
- 17 处代表地标与 120 个具名建筑 / 地点，按政务、商业、学校、医院、文化、办公等分类显示
- 道路名、公园名、水体名、社区/村庄名，带标签避让
- 141 个真实小区名称与边界，按名称或已有别名搜索并高亮范围；小地图和三维场景同步标注
- 搜索小区、道路、建筑、POI、公园、地名
- 搜索结果可直接打开高德 / 百度地图核对同名地点（外部网站需要联网）
- 比例尺、城区边界、`© OpenStreetMap contributors · ODbL` 署名

地图与 3D 共用 `js/shuyang-geodata.js` 的坐标与要素，不存在两套地图对不上的问题。

## 运行

项目是纯静态页面，不需要构建：

```bash
python -m http.server 8123
# 打开 http://127.0.0.1:8123/
```

或者用任意静态文件服务器托管仓库根目录。需要支持 WebGPU 的浏览器（Chrome / Edge 113+，Safari 18+）。

## 地理数据

世界坐标：1 单位 = 1 米，`x` 向东，`z` 向南（北 = `-z`），原点在人民中路与上海中路交叉口。

城区核心的生成结果：1104 条道路中心线、92 条步道/自行车道、1652 个路网节点、1419 条路口间链路、527 个街区、**7,728 条建筑来源记录（OSM / Overture / 影像核对补录）**、63 个水面多边形、49 条河道、29 段铁路与 20 处可传送地标。默认不凭空补楼。建筑来源、筛选与高度方法统计见 [`building-audit.json`](tools/data/shuyang/building-audit.json)，数据获取和限制见 [`BUILDINGS.md`](tools/data/shuyang/BUILDINGS.md)。

道路、水系、用地等基础层来自 OpenStreetMap（© OpenStreetMap contributors, ODbL）；建筑增量和估高分别来自下文注明的Overture与CNBH，地标另有高德地点核对和公开实拍依据：

- `tools/data/shuyang/osm_roads.json` — 道路中心线、宽度、车道与单行
- `tools/data/shuyang/osm_buildings.json` — 建筑轮廓
- `tools/data/shuyang/osm_water.json` — 水面多边形与河道中心线
- `tools/data/shuyang/osm_land.json` — 公园、绿地与用地
- `tools/data/shuyang/osm_pois.json` — 地标/公共设施 POI
- `tools/data/shuyang/osm_places.json` — 街道、社区与村庄
- `tools/data/shuyang/osm_rail.json` — 新长铁路与沭阳站

各查询语句保存在 `tools/data/shuyang/q_*.overpassql`，通过 Overpass API 获取。

## 重新生成数据

已包含裁剪后的来源文件，日常离线重建：

```bash
python -m pip install -r tools/requirements-buildings.txt
python tools/build-shuyang-reviewed-district.py
python tools/build-shuyang-reviewed-water.py
python tools/enrich-shuyang-buildings.py
python tools/build-shuyang-urban.py
python tools/build-shuyang-landmarks.py
python tools/build-shuyang-communities.py
node --max-old-space-size=8192 tools/build-shuyang-geodata.mjs
```

首次下载或更新数据的方法见 `tools/data/shuyang/BUILDINGS.md`。

脚本会写出：

- `js/shuyang-geodata.js` — 道路、路网图、街区、水系、公园、用地、地标与地名
- `js/building-geodata.bin.gz` — SYB2 压缩建筑（7,728 条，含用途、高度来源、底部标高、层数及内院），供 `js/building-geodata.js` 解码

管线包含：

1. 经纬度 → 世界米制坐标（等距圆柱局部切平面）
2. 道路去重、端点聚类成路网图，按宽度/车道/单行生成车道
3. 以 3 m 栅格把车行道从陆地中切出，连通域即路缘岛（街区），再生成地块矩形
4. OSM 标签优先，Overture 按实际多边形重叠去重；内院、多部件和来源属性保留。高度优先使用标签/层数，再采用匹配的模型或 CNBH 有效像元中位数，最后按用途估计
5. 默认仅使用来源轮廓，关闭街区随机补楼；住宅不随机套办公幕墙，商铺仅在商业建筑临街面生成
6. 水面多边形与河道压入 30 m 地面栅格，形成下沉河床与河岸挡墙
7. 地标 POI 与 OSM 建筑匹配，结合 `js/city-config.js` 的 17 处代表地标配置输出模型定位与地块保留区
8. 地标保留区内清除公园树与普通楼栋，保证牌坊、塔楼、体育场等主体不被遮挡

## 目录

- `js/city-config.js` — 沭阳路网、街区、水系、19 处代表地标、传送点与信号相位
- `js/city-grid.js` — 地面、水面、路面、人行道、公园与河岸
- `js/urban-context.js` — 真实步道、停车场、小区用地底色与三维小区名称标注
- `js/buildings.js` — 建筑立面、屋顶细节、店招与流式加载
- `js/road-network.js` — OSM 路网 → 车道、路口、停止线与转向曲线
- `js/street-details.js` — 行道树、路灯、信号灯
- `js/landmarks.js` — 地标的实景参考模型与来源步行桥
- `js/boroughs.js` — 城区外缘绿带（不再生成乡镇）
- `js/city-map.js` — 纯矢量小地图与全屏街道图（建筑/道路/铁路/POI/路名/搜索/比例尺）
- `js/controllers.js` / `cameras.js` — 四种出行方式与机位
